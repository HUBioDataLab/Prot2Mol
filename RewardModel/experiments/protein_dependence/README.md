# Protein dependence of within-assay ligand ranking

## The question

The reward model scores a (protein, molecule) pair. At evaluation we ask it to
order the ligands *inside one assay*, and an assay has exactly one protein.

So: **does the ordering the model produces actually depend on which protein it
was given?**

## Why the question is not rhetorical

Write any pair score in its most general form:

```
s(p, m) = f(p) + g(m) + h(p, m)
```

* `f(p)` protein main effect — how "generally bindable" this target looks
* `g(m)` molecule main effect — how "generally potent" this ligand looks
* `h(p, m)` interaction — the target-specific part, the actual DTI signal

Inside one assay `p` is constant, so `f(p)` is the **same number added to every
ligand**. It cannot change their order. A model of the form `f(p) + g(m)`
therefore produces an *identical ranking for every protein in existence*, while
still looking like it uses the protein — it has a protein encoder, the encoder
has gradients, the score changes when you swap the protein. Only the *order*
does not.

`h(p, m)` is the only term that can make the ranking target-specific.

This experiment measures how much of the ranking is `h`.

## Design

Sample assays uniformly at random from every eligible group (>= 3 ligands,
>= 0.5 pChEMBL span — the same filter the training metric uses). No size cap, no
filtering on how well the model happens to do. Then re-score **the same ligands
of the same assay** under each of these arms:

| arm | what changes | what it tests |
|---|---|---|
| `true` | nothing | the reference ranking |
| `decoy_random_k` | a uniformly sampled different target (k draws) | does an unrelated protein reorder the ligands? |
| `decoy_dissimilar` | the split's *least* 3-mer-similar target (deterministic) | the worst case, not a lucky draw |
| `decoy_shuffled` | the true sequence with residues permuted | matched length and amino-acid composition, destroyed order — rules out "it only reads sequence statistics" |
| `control_molecule` | **the molecule side** is corrupted instead | **the control that makes the result interpretable** |

### The control is the point

A null result is only meaningful if the measurement could have detected an
effect. `control_molecule` corrupts the *other* input by the same kind of
operation — keep the true protein, replace the ligands with random molecules
from other assays.

* If corrupting the **molecule** destroys the ranking, the procedure is sensitive.
* If corrupting the **protein** does not, that asymmetry is the finding.

Without this arm, "swapping the protein changes little" could just mean the
metric is noisy. With it, the two arms are measured the same way on the same
assays, and only one of them moves.

## Metrics

* `rho_<arm>` — Spearman of that arm's scores against measured pChEMBL.
  Answers: *how good is the ranking?*
* `tau_<arm>` — Kendall tau between the **true-protein score order** and the
  arm's score order. Answers: *did the wrong protein reorder anything?*
  This is the direct measurement; it does not depend on the labels at all.
* `rho_mw` — molecular weight alone, a protein-free reference point. Within-assay
  potency tracks molecular size, so this is the score to beat before claiming
  any model skill.

## Statistics

Every arm re-scores the same ligands of the same assay, so the design is
**paired per assay**:

* **One-sided Wilcoxon signed-rank** (`true > decoy`) on per-assay Spearman.
  Non-parametric, because per-assay correlations are bounded and skewed.
* **Cliff's delta** for effect size. `|d| < 0.147` is conventionally negligible.
* **Cluster bootstrap over assays** (10,000 resamples) for 95% CIs, so the
  interval reflects the clustered design rather than treating ligands as
  independent.

A small p-value with a negligible delta means "detectably non-zero, practically
irrelevant" — which is a different claim from "zero", and the numbers are
reported so a reader can tell those apart rather than being asked to trust a
verdict.

## Running it

```bash
python run_protein_dependence.py \
  --ckpt  ../../outputs/<run>/checkpoint-<n> \
  --tag   <name> \
  --split ../../../dataset/processed/chembl_37/<split>/test.parquet \
  --n-assays 400
```

Works on any checkpoint and any split parquet with the standard columns
(`assay_group_id`, `protein_sequence`, `compound_selfies`, `smiles`,
`pchembl_value`, `target_chembl_id`). Seeded; re-running reproduces the sample.

Outputs land in `results/`:

* `per_assay_<tag>.csv` — one row per assay, every arm, for independent re-analysis
* `summary_<tag>.json` — aggregates, CIs, test statistics
* `summary.md`, `fig*.png` — generated by `make_report.py`

## Interpreting the result

| observation | reading |
|---|---|
| `tau(protein swap)` near 1, `tau(molecule swap)` near 0 | the score is a function of the molecule; the protein is a constant offset |
| `rho_true` ≈ `rho_decoy` | the protein contributes nothing to ranking quality |
| `rho_true` ≈ `rho_mw` | the model is not beating a size descriptor |
| `rho_true` >> `rho_decoy` | the model is genuinely target-conditioned |

The headline number is **`rho_true - rho_decoy`**: how much of the ranking
quality is attributable to knowing the protein.
